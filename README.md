# micro-monban（マイクロ門番）

**ラズパイで作る、小さいけれど強い門番。**
自宅や小さな事業所のサーバーの前に Raspberry Pi を1台置き、ルーターやファイアウォールを**補強**する装置です。

[English README](README.en.md) ・ 版: v1.14.3 ・ ライセンス: [Apache-2.0](LICENSE)

> ⚠ **実験的なプロジェクトです。** 個人で開発しており、認証を受けた製品ではありません。無保証です。
> 本番で使う前に、下の「[守れること・守れないこと](#守れること守れないこと)」を必ず読んでください。

## これは何？

サーバーをインターネットや家庭 LAN に**直接つながず**、門番（Raspberry Pi）の内側の**有線1本だけの閉じた区画**に置きます。
外からサーバーへ届く道は、門番の中継（nginx）だけになります。門番はその道で、入ってくるものと出ていくものの両方を見張ります。

```
[インターネット]
      │
[ルーター]  ← 家庭 LAN（192.168.1.0/24 など）
      │
      ├── 門番（Raspberry Pi）の外側口  … 80/443 番だけを公開
      │        │  入口: 簡易WAF・自動遮断   出口: DLP（伏せ字）・個人情報の一括持ち出しガード
      │        │
      │   門番の内側口 10.0.0.1  ── 有線1本・閉じた区画 10.0.0.0/24 ──
      │                                   │
      │                           サーバー役PC 10.0.0.2（Web アプリ 8080 など）
      │
      └── 作業用PC（管理画面・SSH）
```

## 主な機能

| 種類 | 機能 |
| --- | --- |
| 入口 | nftables による入口の制限（80/443 番以外は拒否）、SSH 総当たりの自動遮断、簡易 WAF（スキャナ・パストラバーサル・SQL インジェクション）、怪しい振る舞いの点数化と自動遮断（10分） |
| 出口 | **DLP**: 応答に含まれる機密（API キー、トークン、DB エラー、電話番号など）を伏せ字に。**個人情報 一括持ち出しガード**: 1回の応答や10分間の合計で、個人情報が数件を超えたら止める |
| 自己防衛 | 重要ファイルの改竄検知、予定外の通信・待ち受けポートの検知、緊急ブレーカー（外部入口の遮断／サーバーとの分離をワンクリック） |
| 運用 | 管理画面（HTTPS）、メール通知、**設定レポート**（状態を1つの文書にまとめて定期・変更時にメール。引き継ぎ用）、**インターネット公開ウィザード**（Let's Encrypt／Cloudflare Tunnel） |
| 本体画面 | **HDMI タッチモニター用のダッシュボードと設定**（初期パスワードの変更・Wi-Fi・スイッチ・遮断の解除・メール・自己試験。5分で自動ロック） |

## 守れること・守れないこと

**守れること**
- サーバーを直接さらさない構成そのもの（閉じた区画・転送なし・入口は 80/443 番だけ）
- よくある機械的な攻撃（スキャナ、単純な SQL インジェクションやパストラバーサル、SSH 総当たり）
- アプリの不具合による「出ていく情報」の漏れの一部（鍵・トークン・DB エラー・電話番号などの伏せ字、個人情報の大量送信の停止）

**守れないこと・限界**
- **大規模な DDoS（大量アクセス攻撃）**: Pi 1台と家庭の回線では吸収できません。必要なら Cloudflare などを前に置いてください。
- **WAF は簡易版**です。正規表現の数行による検査で、業務用 WAF のような網羅性はありません。
- **送られてくる本文（POST の中身）は検査しません。**
- DLP と個人情報ガードは**推定**です。すり抜けも誤検知もあります（例: 名前だけの一覧は数えられない、12桁の ID がマイナンバーと誤判定されることがある）。
- **1台構成**です。Pi や SD カードが壊れるとサイトが止まります。予備と復旧手順を用意してください。
- **IPv4 専用**です。
- 運用（OS の更新、警報への対応、ログの保管）は利用者が行う必要があります。

> 💡 外側の広い守り（DDoS・大きな WAF・証明書）は Cloudflare に、内側の細かい守り（アプリに合わせた検査・個人情報ガード・自己監視）は門番に、と組み合わせるのがおすすめです。

## 必要なもの

- **Raspberry Pi 5**（開発・検証機。他の機種は未検証）と microSD カード（16GB 以上）
- **Raspberry Pi OS（64-bit、Bookworm 以降）**
- 有線 LAN ポートが空いていること（閉域側。外側は Wi-Fi か USB-LAN アダプタ）
- サーバー役のPC（Windows または Linux）と LAN ケーブル1本
- インターネットに公開する場合: 独自ドメイン

## 導入の流れ（概要）

```bash
git clone https://github.com/takanyan12/monban.git micro-monban
cd micro-monban
nano install/setup-gatekeeper.sh        # 冒頭の「設定ブロック」を自分の環境に合わせる（HOME_NET など）
sudo bash install/setup-gatekeeper.sh
sudo bash install/setup-gatekeeper.sh --verify
```

1. Pi に OS を入れ、SSH を有効にする
2. このリポジトリを Pi に置き、設定ブロックを直して導入スクリプトを実行（表示された**管理画面のパスワードを控える**）
3. サーバー役PC を設定（Windows は `backend/setup-windows.bat` を管理者として実行）
4. 証明書の鍵 `ca.key` を USB などへ退避し、Pi から消す

詳しくは [導入ガイド](docs/ja/install.md) へ。

## フォルダの構成

```
install/   導入・取り外しスクリプト
src/       管理画面（dashboard.py）・個人情報ガード（pii_guard.py）・本体画面（kiosk.py・kiosk.html）
conf/      nginx・nftables・systemd の設定のひな形、DLP の初期ルール
backend/   サーバー役PC 用の設定スクリプト（Windows／Linux）
tools/     健康診断・本体画面の表示設定・SD の予備とバックアップ・MyDNS の DNS で証明書取得・読み取り専用化・A/B 復旧（実験的）・SHA256SUMS の作成
tests/     自己試験（selftest.sh）・DLP の試験ページ（架空の値のみ）
docs/      説明書（日本語・英語）
```
