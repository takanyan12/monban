# 困ったとき

まずは門番の上で健康診断を実行すると、多くの原因が分かります。
```bash
sudo bash install/setup-gatekeeper.sh --verify
sudo bash tools/gk_check.sh
```

## サイトが表示されない

| 症状 | よくある原因 | 対処 |
| --- | --- | --- |
| **504 Gateway Time-out** | サーバー役PC のファイアウォールが門番からの接続を黙って捨てている | [サーバー役PCの設定](backend.md) のファイアウォール（10.0.0.1 から許可）。Windows はバッチを再実行 |
| **502 Bad Gateway** | Web アプリが動いていない／`localhost` だけで待ち受けている／個人情報ガードが止まっている | アプリを `10.0.0.2:8080` で起動。`systemctl status gatekeeper-piiguard` |
| 何も返ってこない | 門番の nginx が止まっている、ブレーカーが作動中 | `systemctl status nginx`、管理画面のブレーカー表示 |
| ブラウザの証明書警告 | 門番の自前の証明書（LAN 内） | `ca.crt` を端末に登録（[導入ガイド](install.md#6-証明書の鍵を退避する大切)）、または公開用の証明書を使う |

門番から直接確かめる:
```bash
curl -s -o /dev/null -w '%{http_code}\n' http://10.0.0.2:8080/
```

## 本当の利用者が 403 で止められる

| 画面の表示 | 原因 | 対処 |
| --- | --- | --- |
| `Blocked by Gatekeeper WAF: ...` | 簡易 WAF の誤検知 | 内容を確かめ、必要なら `/etc/nginx/snippets/gatekeeper_https_body.conf` の判定を調整 |
| 「個人情報の一括送信を門番が止めました」 | 個人情報ガード | 管理画面の履歴を確認。業務で必要なら件数を上げるか「記録のみ」に |
| 何も表示されない・つながらない | 自動遮断（10分）または許可リスト外 | 管理画面の「動的遮断リスト」で解除。自分の PC は許可リストへ |

## 管理画面に入れない

- **SSH の転送**で入るのが確実です: `ssh -L 9000:localhost:9000 ユーザー名@門番のIP` → `https://localhost:9000/`
- 家庭 LAN 側から直接入るには、管理画面のスイッチが「公開中」である必要があります（`DASH_MODE="switch"` の場合）。
- パスワードを忘れた: 下の「[パスワードを忘れたとき](#パスワードを忘れたとき)」

## SSH がつながらない・時間切れになる

- 家庭 LAN からの SSH は **1分6回まで**（総当たり対策）。続けて何度も接続すると一時的に弾かれます。少し待ってください。
- パスワードを **5分に5回** 間違えると、その PC が **10分間** 自動遮断されます。待つか、閉域側（サーバー役PC）から管理画面で解除してください。
- 自分の PC を許可リストに入れておくと、この心配がなくなります。

## 整合性監視が「注意」「重大」になる

- **予定外の待ち受けポート**: 新しく入れたソフトがポートを開いています。不要なら止めてください（例: rpcbind の 111 番）。
- **改竄の疑い**: 監視しているファイルが変わりました。自分で変えたなら台帳を作り直します（`sudo GK_REBUILD_MANIFEST=1 python3 /opt/gatekeeper/dashboard.py`）。心当たりがなければ、緊急ブレーカーで外部入口を遮断し、調べてください。
- 読み取り専用モードで「重大」を検知すると、120秒後に自動で再起動します。

## メールが届かない

- 管理画面の「テスト送信」の結果を確認してください。
- Gmail は通常のパスワードでは送れません。2段階認証を有効にして **アプリ パスワード** を作ってください。

## 導入スクリプトが「一致しないファイル」「改行が Windows 形式」で止まる

- **改行が Windows 形式（CRLF）**: Windows で ZIP を展開してから Pi に送ったときに起きます。ZIP のまま Pi へ送り、Pi の上で `unzip` し直すか、Pi の上で `git clone` してください。
- **SHA256SUMS.txt と一致しない**: 入手の途中で壊れたか、書き換えられた可能性があります。正しい配布元から入手し直してください。自分で直したファイルだと分かっている場合だけ `sudo GK_SKIP_SUMS=1 bash install/setup-gatekeeper.sh` で続けられます。

## パスワードを忘れたとき

忘れたものによって、やり方が3つあります。上から順に試してください。

### 1. 管理パスワード（管理画面・本体画面）だけ忘れた — SSH には入れる

確かめるだけなら:
```bash
sudo cat /opt/gatekeeper/secret.conf
```
作り直すとき（導入したフォルダで）:
```bash
sudo bash install/setup-gatekeeper.sh --reset-password
```
- 新しい**初期パスワード**を作り、1回だけ表示します。今のパスワードは使えなくなります。
- ほかの設定・記録・証明書はそのままです。
- 本体画面では、最初にまた新しいパスワードを決める画面になります。

### 2. 門番を最初からやり直したい

```bash
sudo bash install/uninstall.sh --purge     # 設定・記録・証明書も消し、ファイアウォールを初期状態に
sudo bash install/setup-gatekeeper.sh      # 入れ直す（新しい初期パスワードが表示される）
```
- 証明書も作り直しになるため、ブラウザや端末に入れた `ca.crt` は新しいものに入れ替えます（`ca.key` を退避してあれば、戻して使い続けることもできます）。
- サーバー役PC の設定は、設定ブロックの値を変えていなければそのままで使えます。

### 3. Pi のログイン（SSH）のパスワードも忘れた

**確実なのは、OS から書き直す全初期化です。**
1. PC で Raspberry Pi Imager を使い、SD カードに Raspberry Pi OS（64-bit）を書き込みます。書き込み前の設定で、ユーザー名・パスワード・Wi-Fi・SSH を決めます。**新しいパスワードは控えておいてください。**
2. [導入ガイド](install.md)の手順で、門番を入れ直します。
3. 上の 2. と同じく、証明書の入れ替えが必要です。

> SD カードのバックアップ（予備カード・イメージ）に戻しても、**中のパスワードは古いまま**なので解決しません。

本体にモニターとキーボードをつなげるなら、OS を書き直さずに Pi のパスワードだけ作り直す方法もあります（上級者向け。OS の版によって手順が変わります）:
1. Pi を止めて SD カードを PC に差し、起動用の区画（bootfs）の `cmdline.txt` の行の末尾に、空白を1つ空けて `init=/bin/sh` を足して保存します。
2. SD を Pi に戻して起動すると、ログインなしの画面になります。次を入力します。
   ```
   mount -o remount,rw /
   passwd ユーザー名
   sync
   ```
3. Pi を止め、SD を PC に戻して `init=/bin/sh` を消し、元に戻して起動します。

> この方法が使えるということは、**SD カードを抜き取れる人は誰でもパスワードを変えられる**ということでもあります。門番は鍵のかかる場所に置いてください。
