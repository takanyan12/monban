# Gatekeeper v1.9 変更履歴（2026-10-31）

## 経緯
「出口対策（Egress Monitoring / DLP）」を巡る外部レビューとの対話を吟味し、設計を修正したうえで実装した。

## 外部提案への吟味と設計修正（8点）
1. 外部提案の nft 例（`inet filter` への直接 insert）は、復旧時に main ルールセットや dynamic_blocks を壊す恐れ → **独立テーブル `inet gatekeeper_breaker` 方式**へ変更。復旧＝テーブル削除のみで、動的遮断リスト・whitelist は影響を受けない。
2. `iif`（IF番号解決、IF不在で插入失敗）→ **`iifname`（文字列照合・安全）**。
3. `ip link set down` は同一セグメントの管理画面も切断する恐れ → **BACKEND_IP 個別DROP**で「バックエンド1台だけ分離」。
4. 通信方向の整理: cut_ext は 入力(EXT_IF) と 転送(EXT_IF→) を遮断し、Pi自身の外向き（緊急メール送信・更新）は生かす。
5. DLPヒット数はnginxログから直接観測できない → **「個人情報パス応答」×「業務操作不在」（URLベース、しきい値・パス設定可）**で代用する旨を明記。
6. メール資格情報は `/opt/gatekeeper/alertmail.json`（chmod 600）に保存し、画面APIには返さない。テスト送信ボタン付き（587=STARTTLS / 465=SSL）。
7. スレッド安全（guard_lock）・メモリ上限（deque maxlen）・stats_gc に新辞書の掃除を追従。
8. セルフDoS防止: 既定 auto_block=OFF、同一理由の再通知は10分クールダウン、ホワイトリスト参照、バナーは15分で自動消灯。

## 新機能
- 出口防御エンジン（4検知器）: 大量ダンプ（単一50MB/10分100MB既定）・個人情報ハーベスト（既定15連続、PIIバースト30件/分）・5xx連発（既定30回/分）・10分累計転送量
- 緊急ブレーカー: 「外部入口遮断」「バックエンドと分離」「復旧」をワンクリック。状態は /opt/gatekeeper/breaker.json に永続化
- 管理者メール通知（非同期送信・テスト送信・最終結果表示）
- ダッシュボードUI: 緊急バナー（復旧/誤検知解除ボタン）・ブレーカーカード・しきい値設定・検知履歴（直近50件）
- 新API: /api/killswitch /api/guard/set /api/mail/set /api/mail/test /api/alert/dismiss
