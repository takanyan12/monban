# インターネット公開

門番を、家庭 LAN の外（インターネット）から見られるようにします。管理画面の「🌐 インターネット公開」カードから操作します。
どちらの方法でも **独自ドメイン**（例: `www.example.jp`、年1,500円前後〜）が必要です。

| | A. Let's Encrypt | B. Cloudflare Tunnel |
| --- | --- | --- |
| 向いている人 | ルーターのポート開放ができる人 | ポート開放が難しい・したくない人 |
| ルーターの設定 | 80・443 番を門番へ転送 | 不要 |
| 証明書 | Let's Encrypt（門番が取得・自動更新） | Cloudflare が用意 |
| 自宅の IP | 公開される | 隠れる |
| DDoS への強さ | 弱い（家庭の回線ごと止まる） | 強い（Cloudflare が受け止める） |

## A. Let's Encrypt（ポート開放ができる人）

1. **DNS**: ドメインの管理画面で **A レコード**を登録します。値は「この家の外向き IP」です（カードの「調べる」で確認できます。外部サービス api.ipify.org に問い合わせます）。
   - 家の IP が変わる契約なら、DDNS（ダイナミック DNS）も必要です。
2. **ルーター**: **80 番と 443 番**を、門番の外側 IP へ転送します（機種ごとに「ポートフォワーディング」「静的 IP マスカレード」などの名前）。
3. 管理画面でドメインと連絡用メールを入れ、利用規約に同意して **「① 事前確認（試験取得）」**。
   - Let's Encrypt の試験用環境で、外から本当に取得できるかを試します（本番の回数制限は使いません）。
   - 失敗したら、原因（DNS／ルーターの転送／別の機器を指している／回数制限）を日本語で表示します。
4. 成功したら **「② 本番取得して公開」**。証明書を取り、そのドメイン専用の設定を有効にします。
5. 証明書は自動で更新されます（`certbot.timer`）。管理画面と設定レポートに残り日数が出ます。

公開をやめるときは「公開をやめる」。証明書は残り、更新も続きます。

> 管理画面（9000番）や、IP を指定した LAN 内のアクセスは、これまでどおり門番の自前の証明書を使います。

### A'. 80 番が外から届かないとき（MyDNS の DNS で確認）

443 番は届くのに、事前確認が「Timeout during connect（外から 80 番に届いていません）」で失敗し続けることがあります。ルーターの転送が正しくても、プロバイダが外からの 80 番を止めている場合です。
DDNS に **MyDNS（mydns.jp）** を使っているなら、80 番を使わずに **DNS で持ち主を確かめる方法（DNS-01）** で証明書を取れます（v1.14.0 から管理画面で選べます）。

1. 管理画面の A で、「持ち主の確認の方法」を **「MyDNS の DNS（80番が外から届かないとき）」** にします。
2. MyDNS の**マスターID とパスワード**（mydns.jp にログインするときのもの）を入れます。門番の中の root だけが読める `/etc/letsencrypt/mydns.netrc` に保存し、自動更新でも使います。画面や記録には出しません。2回目からは「保存済み」と表示され、入れ直すときだけ入力します。
3. 「① 事前確認」→「② 本番取得して公開」。MyDNS への反映を待つので、それぞれ2〜4分かかります。
4. 更新も同じ方法で自動です。**「更新の予行演習」** で、自動更新がうまく動くかを試せます（本物の証明書は変わりません）。結果はカードに「予行演習: 成功／失敗」と出ます。

- ルーターの 80 番の転送は不要になります（443 番だけで足ります）。
- 管理画面を使わずに行うこともできます: `sudo bash tools/le-mydns.sh <ドメイン> <連絡用メール>`（`--reset-login` で ID・パスワードの入れ直し、`--revert` で公開をやめる）。
- 自己試験（`tests/selftest.sh`）が、証明書の残り日数・自動更新・確認用スクリプト・ログイン情報の権限を確かめます。

## B. Cloudflare Tunnel（ポート開放が難しい人）

1. Cloudflare の無料アカウントを作り、ドメインを Cloudflare に登録します（ネームサーバーの切り替えが必要です）。
2. Cloudflare の **Zero Trust → Networks → Tunnels →「Create a tunnel」→ Cloudflared** を選び、表示された**トークン**をコピーします。
3. 同じ画面の **Public Hostname** で:
   - Hostname: 公開したいドメイン
   - Service: **HTTPS** / **localhost:443**
   - Additional application settings → TLS →「**No TLS Verify**」を **ON**（門番の自前の証明書を受け入れるため）
4. 管理画面で「**cloudflared を導入**」（Cloudflare 公式の配布元 pkg.cloudflare.com から入れます。数分かかります）。
5. トークンを貼り付けて「**接続**」。

外すときは「接続を外す」。

### Cloudflare 経由での門番の動き
- **本当の利用者の IP**: cloudflared が付ける `CF-Connecting-IP` を、門番自身（127.0.0.1）から来た要求に限って信頼します。外から同じヘッダを付けても無視されます。
- **自動遮断**: Cloudflare 経由ではファイアウォール（nftables）の IP 遮断が効かないため、遮断した IP は nginx でも拒否します。
- **整合性チェック**: cloudflared の常時接続は「異常な外向き通信」として扱いません。

## どちらの方法でも

- 公開したら、[困ったとき](troubleshooting.md) の確認方法で、外から見えるかを確かめてください（スマホのモバイル回線からのアクセスが手軽です）。
- 管理画面（9000番）は公開しません。インターネットから管理画面に入れる状態にはしないでください。
